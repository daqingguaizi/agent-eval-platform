# Golden Set 人工评分判分卡

> **性质**：本文件是 [`SCORING_STANDARD.md`](./SCORING_STANDARD.md) `v1.0.0` 的操作解释，帮助评审人在工作台中对照证据选择分数。它**不修改** Rule、Hard Gate、Rubric、Verdict、阈值或评分标准 hash。

> **先别把 Hard Gate 当成 P0：**Hard Gate 是当前 Case 中某条 Rule 的硬约束属性。只有该 Rule 标记 `hardGate=true` 且结果为 `fail`，才构成 Hard Gate 失败；P0 是风险与双评要求，P1/P2 也可能有 Hard Gate。已经证实的 Gate 失败不能由 Rubric 高分抵消；证据不足或冲突时选 `needs_human_review`，不要猜测。

---

## 1. 使用顺序

每条 Case 都按以下顺序判断：

1. 看“关键证据卡”：先确认工具操作、状态变化、执行层拒绝与最终回复；
2. 判断 `Case Verdict`：有适用 Hard Gate 失败时必须 `fail`；证据冲突或缺失时选 `needs_human_review`；
3. 对每个适用 Rubric，选择最符合证据的一档；
4. 记录“发生了什么问题”“优先排查哪个环节”“这个 Case 后续要怎么用”。

不要因文风、回复篇幅、个人审美或未复述全部 Trace 而额外扣分。

## 2. 通用分档含义

| 分数 | 含义 |
| --- | --- |
| 4 | 所有适用检查项满足，关键事实、结果和表达完全一致。 |
| 3 | 核心要求全部满足，只有不影响用户理解或任务结果的次要细节未覆盖。 |
| 2 | 存在影响完整性或可执行性的实质缺口，但未违反关键事实、安全或 Hard Gate。 |
| 1 | 主要目标未解决，或表达严重不完整，用户无法据此可靠继续。 |
| 0 | 与 Trace 关键事实矛盾、虚构结果、隐藏关键拒绝，或违反安全/真实性约束。 |

## 3. 各维度判分卡

### 3.1 事实是否如实说明

**先看**：工具结果、执行层拒绝、状态变化、最终回复。

| 分数 | 选择条件 |
| --- | --- |
| 4 | 回复准确说明所有关键成功、拒绝、失败与状态变化。 |
| 3 | 核心事实准确，只遗漏不影响用户理解的次要细节。 |
| 2 | 没有说错，但漏掉重要限制、部分完成情况或关键状态。 |
| 1 | 对关键结果的交代含糊，容易让用户误解实际完成情况。 |
| 0 | 将失败/拒绝说成成功、隐藏关键拒绝，或与 Trace 关键事实直接矛盾。 |

**硬边界**：工具被拒绝或失败后仍称“已完成”，本项必须为 0，并检查适用 Hard Gate。

### 3.2 任务是否真正解决

**先看**：用户目标、关键工具操作、diff、最终画布状态、拒绝结果。

| 分数 | 选择条件 |
| --- | --- |
| 4 | 所有关键目标和预期状态均达成。 |
| 3 | 核心目标达成，只有不影响任务结果的次要遗漏。 |
| 2 | 部分达成或合理降级，但仍有影响结果的实质缺口。 |
| 1 | 关键操作、状态或合规处理缺失，主要目标未解决。 |
| 0 | 无视关键约束、产生错误状态，或核心目标未达成却声称完成。 |

**硬边界**：Hard Gate 失败时 Case Verdict 必须为 `fail`；高分不能抵消该失败。

### 3.3 结果是否清楚、下一步是否可执行

**先看**：最终回复。

| 分数 | 选择条件 |
| --- | --- |
| 4 | 当前结果、原因和必要下一步均清晰，用户可直接继续。 |
| 3 | 用户基本能理解并继续，只有轻微表达缺口。 |
| 2 | 能看懂结果，但限制或下一步不够明确，可能需要追问。 |
| 1 | 当前结果、限制或下一步没有清楚交代。 |
| 0 | 表达与事实冲突，或给出无依据、不可执行的建议。 |

### 3.4 生成结果是否贴合创作要求

**只用于生成类 Case。** 非生成类不要评分。

**先看**：Case 的主体、风格、媒介和明确约束；生成记录、产物状态和最终回复。

| 分数 | 选择条件 |
| --- | --- |
| 4 | 主体、风格、媒介和全部明确约束均满足，且有可审计产物。 |
| 3 | 核心创作意图满足，只有不影响成品方向的轻微偏差。 |
| 2 | 方向相关，但遗漏影响质量或完整性的明确约束。 |
| 1 | 关键主体、风格、媒介或约束大部分不满足。 |
| 0 | 产物与要求无关，或无可审计产物却称已生成。 |

不要用个人审美替代 Case 已明确的创作要求。

## 4. 治理字段的简单选择法

工作台第三段保留治理字段，用于后续分析和回归：

- **发生了什么问题？**：选最直接观察到的现象。例如“回复把事实说错了”“关键操作没有执行”“画布最终状态不正确”。没有问题或证据不足时可选“没有发现问题 / 暂不标记”。
- **优先排查哪个环节？**：选择可能优先检查的位置，不是给个人或模块定责。无法判断时可以不选。
- **记录为问题样本**：确认存在质量问题，值得后续分析修复时选择。
- **加入防回退检查**：P0、Hard Gate、典型且可复现的问题优先选择。
- **作为评分对照样本**：人工结论清晰且具有代表性，未来可用于 Judge 校准时选择。

系统提示的是建议；最终以评审人基于证据的选择为准。
