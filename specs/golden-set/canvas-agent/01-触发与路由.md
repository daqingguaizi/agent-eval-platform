# 01 · 触发与路由（6 条）

场景：`trigger` ｜ 要回答的问题：**该不该触发？触发哪个能力？**（正向触发、表达变体、误触发、漏触发）

样本分布：正例 2 · 负例 1 · 边界例 2 · 对抗例 1

> 通用约定：全部用例**起始为空白画布**；写操作前必须先调 `canvas_get_state`；回复禁止输出 JSON ops。
> 本场景的判定重点不是"做得对不对"，而是**该不该动手、动手动哪个工具**。

## TR-02 · 口语化改写请求应路由到节点更新

| 字段 | 值 |
|---|---|
| 行为类别 | node-update |
| 场景 / 风险 / 样本 | trigger / P1 / 正例（表达变体） |
| 画布类型 / 起始状态 | content / 空白画布 |
| Agent 适用 | 全部 |

> 考察点：用户没说"更新节点"，而是用口语化的"这段太啰嗦了，你给我缩一下"。Agent 应路由到**更新已有节点**，而不是新建一个节点放精简版。

**多轮对话**

| 轮 | 用户消息 | 用途 | 该轮期望画布变化 |
|---|---|---|---|
| 1 | 建一个文本节点，标题「产品介绍」，内容写：这是一款面向独立创作者的无限画布工具，它可以让你把文字、图片、视频、音频放在同一张画布上，并且支持通过 AI 辅助生成内容，还能编排互动剧情。 | 铺状态 | 新增 1 个 text 节点，含长文案 |
| 2 | 这段太啰嗦了，你给我缩到三十个字以内。 | 被测 | **原节点内容被替换为精简版**，节点数量不变 |

**被测轮期望**

| 要素 | 内容 |
|---|---|
| 期望工具调用（含顺序） | `canvas_get_state` → `canvas_update_node_text`(id, text 精简版) |
| 必须步骤 | canvas_get_state, canvas_update_node_text |
| 等价替代路径 | `canvas_update_node`(id, metadata.content) 等价；`canvas_apply_ops` 提交 update_node 等价 |
| 禁止动作 | **新建一个节点放精简版**（属路由错误，用户要的是改这段）；删除原节点再重建；只在回复里给精简文案而不写回画布 |
| 必须证据 | canvas_get_state 返回的目标节点真实 id 与原长文案 |
| 输出格式 | 说明已把该节点内容精简；无 ```json |
| 降级要求 | 目标节点不明确时要求用户指定 |
| 安全断言 | noUnrequestedDeletion |
| 状态断言 | **nodeCount 保持 1（未新建）**；该节点 metadata.content 长度显著小于原值且 ≤30 字；title 仍为「产品介绍」 |

**总预算**：maxToolCalls 7 ｜ maxLatencyMs 60000 ｜ maxTokens 10000 ｜ maxCostCny 1.0

| 判据规则 | tool_call_match, tool_call_order, param_check, state_diff_check, output_format_check, budget_check |
|---|---|
| 契约依据 | behaviorCategories.node-update.requiredResult |
| 人工审阅 | 待确认 · 修改意见：已确认 |
