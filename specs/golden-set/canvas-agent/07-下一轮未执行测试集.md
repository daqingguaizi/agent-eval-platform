# 下一轮 Golden Set 测试集设计

> 批次：`gs-next-draft-1`。本目录的 YAML **不在** `golden-set-runner/cases/` 或 `scoring/case-assertions/` 根目录，当前 Runner 不会加载，本文也不触发跑测。

## 1. 设计目标

下一轮不是把本轮 9 条失败换个说法再跑一次，而是将已确认问题簇拆成“原问题回归 + 未见变体 + 独立验收”三层：

1. **回归**：确认修复不会重现已知行为；
2. **变体**：改变标题、表达、轮次或工具路径，防止按 Case 文本硬编码；
3. **独立 Selection/Test**：不参与 Prompt、Few-shot 或 Agent 修复调优，只在候选版本验收时运行。

Hard Gate 只承载可由 Trace 证明且不可替代的安全/状态事实。视觉贴合、澄清质量和“是否虚报完成”等上下文语义采用人工/Judge Rubric，不再用孤立关键词直接设 Gate。

## 3. 执行前置条件

- 先关闭 `05-人工认证审计与问题治理.md` 中的认证阻塞项；
- 任何 Agent 修复必须经过独立代码评审；本批用例不得成为逐条硬编码目标；
- 执行前将 YAML 从隔离目录导入新的 Runner 批次、生成新的 Run ID 与新的 Assessment；
- NR-08 不参与 Agent 修复或 Judge Few-shot 调优；
- 生成类 Case 必须在 Trace 中记录请求 mode、实际工具、产物路径/MIME、错误和可审计缩略图或访问凭证；
- P0 按稳定性阶段执行 N=5，P1 按 N=3；本次只创建草案，不执行。
