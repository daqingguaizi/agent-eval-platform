## 3. 已确认问题簇与修复方案

### G-01：歧义请求被擅自执行

- **Case**：CL-15、CL-18、CL-21、EX-05、OQ-07。
- **现象**：删除、连线或更新对象在用户未明确指代/确认时被执行；OQ-07 还暴露原始节点 ID 作为用户可见澄清信息。
- **根因假设**：规划层缺少“高影响写操作前的歧义检测”；工具协议可执行但没有要求 Agent 显式收集候选或确认。
- **置信度**：高（均有最终状态与工具步骤证据）。
- **修复方向**：在 Agent 决策规范中将删除、连线、批量更新列为“对象歧义即停”的操作；先读状态，返回真实候选标题和可选项；禁止把内部 ID 作为唯一澄清信息。
- **禁止方案**：按 CL-15/18/21/OQ-07 的固定词汇表硬编码；仅靠最终回复补一句澄清而实际已经写入。
- **验收**：NR-01、NR-02、NR-03、NR-04。

### G-02：生成意图、模式和产物事实脱节

- **Case**：CL-22、CL-23、CL-24、OQ-03。
- **现象**：请求图/视频/文本时模式或产物类型错误；生成结果和提示词意图不匹配；回复掺杂英文或声称未实际生成的类型；Trace 缺少结构化 generation 记录。
- **根因假设**：Agent 对 generation mode 的选择与回填链路不一致；无头 Runner 将部分 text 任务落入默认 image 分支；生成产物的视觉语义未进入确定性证据包。
- **置信度**：高（CL-24 的两张图片替代文本+图片、CL-23 未执行视频链路）；视觉不贴合的具体模型根因需下一轮多样本验证。
- **修复方向**：修复前先定义“请求媒介 → 生成模式 → 工具调用 → 产物类型 → 用户回复”的一致性契约；Trace 记录实际 mode、请求参数、产物路径、错误与 MIME；视觉贴合度交给具备实际产物输入的多模态 Judge/人工。
- **禁止方案**：只改最终回复文案；把不存在的生成记录补写进历史 Trace；以单个随机图像反推全部模型质量。
- **验收**：NR-05、NR-06、NR-07。

### G-03：Rule Binding 与语义边界待收敛

- **Case**：CL-25、OQ-08。
- **现象**：CL-25 的 Sidecar 将 `canvas_apply_ops` 设为必须 Gate，但用例明确允许拆分调用，这是已证实的 Rule Binding 矛盾；OQ-08 的输出既说明选项节点被拒，又出现“全部完成”，是否允许这种自相矛盾表述属于需要产品确认的语义边界，而不是自动的关键词误判。
- **根因结论**：CL-25 为高置信评分规则缺陷；OQ-08 经用户决策允许结合完整上下文作出语义判断，不再以绝对完成短语单独触发 Gate。
- **已采取方向**：已新建并冻结 `baseline-v1-agent-quality-r1`。CL-25 将等价路径写入独立 Binding；OQ-08 移除关键词 Hard Gate、保留人工语义复核。两个 Case 仅使用现有 Trace 重评，既有 A/B 结论已以 `supersedes` 迁入后继 Assessment。
- **禁止方案**：在旧 `baseline-v1` 直接改 Rule 或覆盖人工 Review；用高 Rubric 分抵消已证实 Gate fail。
- **验收**：NR-07、NR-08。
