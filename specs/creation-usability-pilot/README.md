# 创作者创建易用性试点评审包

> 状态：仅供逐条人工确认。不是 Runner 输入；不得启动 Agent、模型、Runner、冒烟、试跑或评分。

## 范围与隔离

- 本包与 `golden-set-runner/cases/`、既有 50 条 Golden Set、运行记录完全隔离。
- 全部 `CP-*` Case 固定 `initialState: blank`；Case 间不得继承节点、资产、连线、会话或生成结果。
- `canvasType: content | story` 只定义空画布类型，不是预置画布内容。
- 图片输入 Case 的首轮附件由 Runner 复刻用户在 Agent 输入框上传图片的产品路径：上传自动创建真实 image 节点；文字提示词与附件在同一轮发送。部分 Case 同轮上传两张参考图，验证多参考关系。
- 视频输入 Case 保持空白画布：Runner 通过真实画布视频上传路径创建最小 video 节点集合，再让 Agent 在后续对话轮读取并编辑这些节点；当前试点含一条双视频参考候选和一条图视频混合参考候选。
- 全景与音频 Case 覆盖新版已注册的 `plugin:panorama` 节点和 `audio` 生成模式；全景 Case 还验证生成结果必须回写到同一全景节点。
- 被测项目固定为 `../../products/echo-infinite-canvas-8.12/`；本评审包不运行任何产品或评测任务。

## Case 字段

| 字段 | 含义 |
| --- | --- |
| `sourceTaskIds` | 直接使用时的 ComfyBench 来源任务 ID；`canvas-native` Case 为空 |
| `tier` / `modality` / `taskPattern` | 用于覆盖报表和来源能力追溯 |
| `supportStatus` | `direct`、`provider_gated` 或 `approximate`；不是实际运行结论 |
| `input.turns` | 同一 Case 内的前置轮和目标轮；`target` 是本次验证点 |
| `attachments` | 首轮 Agent 输入框附件；图片附件须自动落为画布 image 节点 |
| `resourceRefs` | 仅引用指定本地资源，不复制二进制 |
| `acceptance` | 目标轮的可核验证据、结果要求、禁止动作和降级口径 |
| `riskFlags` | 供人工确认优先关注的风险 |

## 资源接入规则

1. 图片输入 Case 从空白画布开始。Runner 校验 `resourceRefs` 后，将图片作为**同一目标轮**的 Agent 输入框附件与文字提示词一起发送；必须复刻最新产品的“附件上传 → 自动创建 image 节点 → 文本节点/生成链路”行为。
2. 图片附件不可仅作为模型视觉上下文；Trace 必须记录自动创建的真实 image 节点、同轮文本节点、引用连线、生成配置和结果节点/真实错误。
3. 视频输入 Case 从空白画布开始。Runner 走真实视频上传路径创建最小必要的 video 节点集合；该上传步骤是 Case 内的受控前置条件，不计入 Agent 得分。目标轮必须使用这些节点的真实 ID。
4. 多参考 Case 必须明确每份输入的创作角色，并在 Trace 中记录每个真实节点、参考连线与实际送入 Provider 的媒体数量；Provider 不支持多参考时必须如实降级或报错。
5. 全景 Case 必须先验证 `panorama` 插件已启用；成功时生成结果只可回写同一 `plugin:panorama` 节点，失败时不得降级创建普通节点冒充。
6. 未验证最新产品协议前，图片附件自动入画布、视频上传和参考视频 Provider 支持都标为运行前置条件；不得伪造节点 ID、上传状态或生成产物。
7. `resourceRefs` 只指向指定本地资源目录。公众人物、可识别艺人/偶像、受版权保护标识、移除水印及中文整理包已排除的内容不得进入试点。

全量媒体登记、SHA-256、来源任务和限制见 [`resource-registry.yaml`](resource-registry.yaml)。

## 人工逐条确认清单

审阅每个 `cases/CP-*.yaml` 时确认：

1. 创作意图、来源 ID 与难度是否合适；
2. 每条是否从隔离的空白画布开始，且未跨 Case 继承状态；
3. 图片 Case 是否以“同轮附件 + 文本提示词”复刻真实 Agent 输入体验；
4. 视频 Case 是否仅经真实上传路径建立最小 video 节点；
5. 资源是否仅引用指定目录中的允许文件；
6. `direct`、`provider_gated`、`approximate` 的口径是否符合预期；
7. 验收是否保留真实节点、连线、产物/错误和状态差异证据；
8. 是否应保留、改写、替换或删除该 Case。

确认 30 条后，才讨论 Runner 协议适配、冒烟、试跑、正式 200 条建集与评分。
