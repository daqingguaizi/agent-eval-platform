# 创作者试点评分与归因规范

- **Spec 版本**：`1.5.0`
- **状态**：生效
- **适用样本**：`creation-usability-pilot` 的 CP-01 至 CP-30 及其 Echo Run
- **唯一准绳**：评分器、DeepSeek V4 Pro 任务包、人工评审、Viewer 与研发报告均以本规范为准；变更必须先修改本文件并补充变更记录。

## 1. 目标与边界

本规范将“浏览器跑测完成”与“任务高质量完成”严格分开。原始 `run.json`、`evaluation-state.json`、Trace、画布快照、媒体归档和截图是只读运行事实；评分只能写入 Run 下独立的 `scoring/` 目录。

评分同时服务于：逐案质量判断、失败与低质量成功归因、人工复核、可追溯研发问题簇和后续回归。50 条 GS 与 30 条 CP 必须独立展示，禁止汇总成同一通过率。

## 2. 状态机

- **运行状态**：沿用原始 Run 的 `completed`、`failed`、`blocked`，不由评分修改。
- **评分状态**：`待人工评审`、`通过`、`通过但有改进项`、`部分完成`、`失败`、`不可评估`。
- **人工记录**：新增评审时追加保存；一条记录可标记 `isCurrent=true`。每个 Case 最多一条当前有效记录；设为当前有效时旧记录自动保留但失效。
- **编辑窗口**：最终研发报告尚未生成时，Viewer 允许评审者直接编辑任意已完成记录。保存时覆盖该记录的评分、结论、归因、说明和建议，记录 ID 与创建时间保持不变。最终报告文件生成后，评审记录冻结；如需更正，必须开启新的评分轮次。
- **待确认**：两条有效候选结论冲突或评审者显式标注时设为 `待确认`；后续评审可追加或直接编辑既有记录，不设裁决者角色。
- **报告门禁**：30 条均有当前有效人工结论；`失败`、`部分完成`、`不可评估` 均有至少一条完整归因；每一条证据路径存在。未满足时禁止生成最终研发报告。

## 3. 三层证据、总分与最终结论

### 3.1 三层证据分别回答什么问题

| 层级 | 回答的问题 | 允许使用的证据 | 产出 | 对最终结论的作用 |
| --- | --- | --- | --- | --- |
| 确定性证据 | 运行事实是否存在、是否完整、是否触发硬阻断？ | Run 状态、目标轮、画布快照、媒体清单、归档媒体、Trace、人工接管记录 | 规则通过 / 失败 / 不适用 / 需人工复核 | 可阻断“通过”；不能单独证明质量好 |
| DeepSeek V4 Pro 辅助评审 | 产物、画布和反馈从可见证据看是否符合任务？ | 任务要求、确定性摘要、归档媒体、视频关键帧、画布快照、最终截图 | 适用维度 0–5 分、置信度、发现、引用证据、人工重点核验项 | 为人工提供可复核意见；不能决定最终状态 |
| 人工评审 | 产物是否真正可用、审美与编辑体验是否达标、问题应如何归因？ | 前两层全部证据，以及人工播放/查看得到的事实 | 五维原始分、总分、最终状态、归因、建议 | 最新有效人工记录是最终质量主依据 |

**判定顺序**：先检查确定性硬阻断；再查看模型辅助意见；最后由人工基于全部证据打分和定状态。任何一层缺失都必须明确标注，不能以默认通过补齐。

### 3.2 五个维度、权重与评分锚点

总分为 100，仅用于排序、切片和趋势，不替代最终人工状态。人工当前有效记录中的可用维度原始分按下式换算：

\[
总分 = \frac{\sum_{i \in 适用维度}(原始分_i / 5 \times 权重_i)}{\sum_{i \in 适用维度}权重_i} \times 100
\]

`N/A` 不记为 0 分，会从分母中移除；只有确实无法凭证据判断时才可使用。确定性评分和模型评分是人工打分的证据输入，系统不会自动把三层分数相加，也不会用模型分数覆盖人工分数。

| 维度 | 权重 | 主要来源 | 评审时必须判断的内容 |
| --- | ---: | --- | --- |
| 执行与证据完整性 | 20 | 确定性证据 + 人工确认 | 目标轮是否完成；画布快照、Trace、输出媒体是否可读且相互一致；是否存在硬阻断 |
| 任务完成与工具编排 | 20 | 确定性证据 + 模型辅助 + 人工 | 是否理解任务；模态、关键节点、连接和工具顺序是否合理；是否遗漏关键步骤或产生无关操作 |
| 画布可用性与可编辑性 | 15 | 模型辅助 + 人工 | 节点是否结构清楚、状态一致、可继续编辑；是否残留错误、空节点或难以理解的结构 |
| 产物质量与需求符合度 | 30 | DeepSeek V4 Pro + 人工 | 主体、场景、风格、动作/镜头、时长、参考约束、清晰度、稳定性和明显瑕疵是否满足要求 |
| 交互可靠性与边界行为 | 15 | 确定性证据 + 模型辅助 + 人工 | 系统是否如实反馈成功或失败；失败后是否说明原因、保留已完成工作并给出可恢复的下一步 |

五维统一采用以下原始分锚点。人工和模型均须按同一含义理解分数；模型不能确认时填 `N/A`，人工不能确认时应先补充证据或标记“不可评估”。

| 原始分 | 含义 | 可操作判据 |
| ---: | --- | --- |
| 5 | 完整满足 | 关键要求均有证据支撑，无明显质量、结构或真实性问题；可直接交付或继续编辑 |
| 4 | 基本满足 | 核心要求满足，仅有不影响主要使用的轻微瑕疵或可选优化项 |
| 3 | 部分满足 | 可见主要结果，但存在需要修正的明确缺口、质量问题或编辑障碍 |
| 2 | 明显不足 | 仅完成部分关键要求，或关键约束、结构、质量存在实质问题 |
| 1 | 接近失败 | 核心任务大多未完成，或产物/反馈与需求明显不符 |
| 0 | 不成立 | 没有目标结果、关键事实矛盾、产物不可用，或将失败伪称成功 |
| N/A | 无法评估 | 缺少必要媒体/证据或该维度对该 Case 客观不适用；必须说明原因 |

### 3.3 硬阻断与最终状态

确定性硬阻断只包括直接违反用户任务的事实：用户目标轮未完成、未读取当前画布就执行、未调用完成用户目标所需的工具、未生成用例要求的画布结构，或在内容画布中写入互动剧情运行态结构。画布快照、媒体归档、网络 Trace 等只作为读取这些用户行为的证据来源；它们自身缺失不会单独构成质量失败，而应标记为“需人工复核”。

发生硬阻断时，最终状态只能是“失败”或“不可评估”。唯一例外是人工能引用明确证据证明阻断来自评测基础设施误判；此时必须归因为 `evaluation_gap` 并说明不采纳该阻断的理由。即使总分较高，人工最终状态仍优先于总分。

## 4. 确定性规则

确定性评分只验证**用户实际使用时可感知的 Agent 行为是否满足任务**，不评价审美或语义质量。它回答的是：Agent 是否跑通目标轮、是否先理解当前画布、是否调用完成任务所需工具、是否生成了要求的节点/连线结构、以及是否遵守内容画布与互动剧情结构的隔离边界。

画布快照、网络 Trace、媒体清单和归档文件只用于读取上述行为的证据；它们不是评分目标。换言之，“拿到了快照”“生成了媒体清单”“归档了媒体”本身不等于用户任务完成；这些资料无法读取时应标记为“需人工复核”，而非单独扣分或硬阻断。

每条结果必须保存技术规则 ID、中文检查项、状态、原因、用户任务证据路径与可选修复建议。规则状态含义如下：

| 状态 | 含义 | 评分处理 |
| --- | --- | --- |
| 通过 | Agent 行为满足用户任务对应的检查条件 | 该规则记为 100，用于相关确定性维度的证据摘要 |
| 失败 | Agent 行为直接违反用户任务对应的检查条件 | 硬阻断规则会限制最终状态；非硬阻断规则进入人工复核 |
| 不适用 | 该 Case 客观不需要该行为，例如澄清缺失输入时不要求写入节点 | 不计入该规则维度平均值 |
| 需人工复核 | 无法从现有运行资料读取真实 Agent 行为 | 不记为通过，也不自动判失败；必须由人工说明 |

首版规则目录：

| 中文检查项 | 技术 ID | 如何判断 | 硬阻断 | 用户任务价值 |
| --- | --- | --- | --- | --- |
| 用户目标轮已执行 | `AGENT_TARGET_TURN_COMPLETED` | 用例定义的目标轮存在且执行完成 | 是 | 用户请求没有在目标轮中失败或中断 |
| 已读取当前画布 | `REQUIRED_CONTEXT_READ` | 在处理前调用 `canvas_get_state` | 是 | Agent 能基于真实画布类型、已有节点、附件状态和 ID 决策，不凭空猜测 |
| 已调用完成任务的必要工具 | `REQUIRED_USER_OPERATION` | 生成任务调用对应生成流/生成工具；编排任务调用创建或连接工具；澄清/拒绝类不要求写工具 | 是（适用时） | Agent 真正执行用户所需操作，而非只给出文字承诺 |
| 已形成用户要求的画布结构 | `EXPECTED_CANVAS_STRUCTURE` | 生成任务具备文本、配置和对应媒体节点，且目标媒体节点为成功状态并有可用内容；故事编排具备用例要求的章节/剧情/选择/游戏结构 | 是（适用时） | 用户可以在画布中看到并继续编辑所要求的可用结果，而非只有空节点或失败节点 |
| 内容/剧情结构隔离 | `CONTENT_STORY_ISOLATION` | 内容画布不得写入互动剧情节点或运行态分支连线；画布类型必须保持用例要求 | 是（隔离 Case） | 防止在错误画布里创建不可用的交互结构，也不以普通文本伪装互动节点 |
| 失败、限制和缺输入反馈真实 | `USER_FACING_FAILURE_TRUTHFULNESS` | 隔离、缺参考、生成失败等场景的最终回复说明真实限制和可执行下一步 | 否 | 用户不会被伪成功、静默失败或随意替换素材误导 |

以下项目明确**不属于确定性评分规则**：`EVIDENCE_CANVAS_SNAPSHOT`（画布快照可读）、`EVIDENCE_ARTIFACT_MANIFEST`（媒体清单可读）、`OUTPUT_MEDIA_PRESENT`（归档输出媒体存在）和 `NETWORK_NO_CREDIT`（是否发起积分请求）。它们最多作为审计或人工复核资料，不能代表用户需求是否满足，也不参与总分、硬阻断或最终状态。

## 5. DeepSeek V4 Pro 模型辅助评审

模型固定为 `deepseek-v4-pro`，通过当前 IDE 窗口人工切换后执行；不得以其他模型静默替代，也不通过额外 API 自动调用。

### 5.1 输入与边界

评分器为每个可评估 Case 输出任务包，包含：任务要求、确定性证据摘要、画布/产物证据路径、输入输出媒体、视频关键帧、Rubric、JSON 输出契约及本 Spec 版本。视频至少采集开头、中段、结尾三帧；结论必须引用时间点，不能只根据封面判断运动。

模型只根据任务包内可读取的证据打分。无媒体、媒体不可读或模型无法访问时必须填 `N/A` / `未执行`，并在 `humanFocus` 中说明缺少什么；不得猜测未展示的画面、运动或用户体验。

### 5.2 模型按维度的评分规则

模型输出四个适用维度的 0–5 分，并复用第 3.2 节的统一分数锚点；每个分数必须能由任务要求、可见媒体、画布或确定性证据解释。

| 模型维度 | 模型必须检查 | 典型扣分情形 |
| --- | --- | --- |
| 产物质量与需求符合度 | 主体、场景、风格、构图、动作/镜头、时长、参考素材保持、文字/禁用约束、清晰度与瑕疵 | 主体或场景错、镜头/动作未体现、参考图不保留、乱码文字、明显变形、视频运动无法核验 |
| 任务完成与工具编排 | 任务要求与画布节点、连接、生成结果是否对应；是否选择正确模态；是否遗漏关键生成或连接步骤 | 错误模态、关键节点/连接缺失、仅写概念节点未生成、明显无关或重复操作 |
| 画布可用性与可编辑性 | 节点状态是否成功、信息是否可理解、结构是否可继续修改、是否残留错误或未完成节点 | 错误/空闲节点未解释、输出难以定位、结构缺少关键输入、节点状态与反馈矛盾 |
| 交互可靠性与边界行为 | 最终反馈是否与确定性证据一致；失败、能力限制和缺输入时是否如实说明且不伪造成功 | 将失败描述为完成、隐瞒服务限制、缺输入时擅自替换、反馈与画布/媒体事实冲突 |

每份模型结果必须保存：`modelId=deepseek-v4-pro`、任务包 ID、提示词/Rubric/Spec 版本、关键帧策略、执行时间、每维分数、置信度、发现、证据引用、问题标签、人工重点核验项与原始输出。模型不决定最终状态，也不覆盖人工结论。

## 6. 人工评审

### 6.1 人工评审前的操作顺序

1. 先查看“评分如何形成”中的硬阻断和总分规则。
2. 在“确定性规则与证据”中确认自动事实，并打开存在疑问的证据链接。
3. 查看模型评分的每维分数、依据、发现和“人工重点核验项”；视频/音频必须实际播放后再判断运动、稳定性或声音质量。
4. 按五个维度分别打 0–5 或 `N/A`，填写最终状态、评审说明和研发建议。
5. 选择“通过但有改进项”“部分完成”“失败”或“不可评估”时，只需在评审说明中写清观察到的事实、用户影响和依据；**不要求人工判断发生阶段、责任域、严重度或建议责任模块**。
6. 全部人工评审完成后，系统以评分、评审说明、研发建议、确定性证据和模型结果为输入，由后续归因模型生成候选问题簇，再由产研评审确认归因、责任域和优先级。

### 6.2 人工五维填写指引

| 字段 | 应看什么 | 5 分示例 | 3 分示例 | 0 分示例 | `N/A` 何时可用 |
| --- | --- | --- | --- | --- | --- |
| 执行与证据完整性 | 目标轮、必要工具调用、所需节点/连线和隔离边界是否满足 | 目标轮完成，先读取画布并完成必要行为 | 结果存在但有明确工具、结构或隔离问题待修正 | 用户目标轮未执行，或直接违反任务关键边界 | 无法读取实际 Agent 行为且不能补充 |
| 任务完成与工具编排 | 指令理解、模态、节点、连接、步骤 | 正确选择模态并完成所有关键节点和连接 | 主结果存在，但有遗漏、重复或不够合理的步骤 | 错模态或核心步骤未执行 | 任务本身不要求编排且无可判断结构 |
| 画布可用性与可编辑性 | 节点结构、状态、可继续编辑性 | 节点清楚、状态正确、可继续修改 | 可编辑但有命名/布局/残留节点问题 | 结构损坏、关键输出找不到或持续报错 | 没有画布快照且无法访问画布 |
| 产物质量与需求符合度 | 产物是否满足具体任务要求；视频要播放核验 | 主体、场景、动作/镜头、约束和质量均满足 | 主结果可用但有明显瑕疵或约束遗漏 | 无产物、完全不符合关键要求或不可用 | 媒体不可读，且无法据其他可靠证据判断 |
| 交互可靠性与边界行为 | 反馈真实性、失败恢复、边界说明 | 成功/失败如实说明，失败后给出可执行下一步 | 基本真实但信息不全或恢复建议较弱 | 隐瞒失败、伪称成功或误导用户 | 没有可读回复、Trace 或人工观察记录 |

最终状态选择规则：

| 状态 | 何时选择 |
| --- | --- |
| 通过 | 五维无关键缺口；所有关键需求已满足；无硬阻断 |
| 通过但有改进项 | 可正常交付，但存在不影响主要使用的轻微缺陷；需写明改进建议 |
| 部分完成 | 部分关键要求完成，但仍有需要修复的实质缺口；在评审说明中写清事实和用户影响 |
| 失败 | 核心任务未完成、产物不可用、反馈失实，或存在不能被基础设施误判解释的硬阻断；在评审说明中写清事实和用户影响 |
| 不可评估 | 缺少必要证据、媒体不可读或评测基础设施问题导致无法给出可信判断；在评审说明中写清缺失的依据 |

每条 Case 至少一条人工评审。最终研发报告生成前，评审者可直接点击任意历史记录的“编辑”：Viewer 预填该记录的评分、结论、说明和建议；保存后直接覆盖该条记录。最终报告生成后记录冻结。建议对“失败”“部分完成”“不可评估”追加第二次评审，对其他状态进行抽检。Viewer 必须展示完整历史、当前有效记录和待确认标记。

## 7. 归因 Taxonomy

归因不是人工评分表单字段。全部人工评审完成后，归因模型根据人工评分、评审说明、研发建议、确定性规则和模型辅助评审生成候选归因；产研评审再确认候选归因。单 Case 可包含多条已确认归因；每条归因必须有阶段、现象、责任域、性质、严重度、置信度、证据、影响说明、建议动作和建议责任模块。

- **阶段**：`case_definition`、`agent_planning`、`tool_selection`、`parameterization`、`generation_execution`、`canvas_write`、`media_storage`、`workspace_sync`、`evidence_archive`、`viewer`、`evaluation_design`。
- **现象**：`not_triggered`、`wrong_modality`、`duplicate_generation`、`wrong_connection`、`timeout`、`state_mismatch`、`media_missing`、`constraint_violation`、`quality_insufficient`、`misleading_feedback`、`not_reproducible`。
- **责任域**：`case_spec`、`runner`、`canvas_agent`、`canvas_frontend`、`workspace_sync`、`model_or_provider`、`media_service`、`scorer`、`viewer`。
- **性质**：`functional_failure`、`reliability`、`quality_debt`、`ux`、`safety_boundary`、`evaluation_gap`、`external_dependency`。
- **严重度**：`P0`、`P1`、`P2`、`P3`。

报告按“阶段 + 现象 + 责任域”聚合为问题簇，列出影响 Case、证据、频率、最高严重度、建议优先级和回归 Case。
